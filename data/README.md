## 四、本地实际统计（重新扫描，非官方数字）

### 4.1 每类文件数量

| 类别目录 | 实际张数 | 占比 | 官方表述 |
| --- | ---: | ---: | --- |
| `A220` | **464** | 15.30% | 约 500 |
| `A320321` | **510** | 16.82% | 约 500 |
| `A330` | **512** | 16.89% | 约 500 |
| `ARJ21` | **514** | 16.95% | 约 500 |
| `Boeing737` | **528** | 17.41% | 约 500 |
| `Boeing787` | **504** | 16.62% | 约 500 |
| **合计** | **3032** | 100% | 3032 |

**核对结论**：

- **总数与官方一致**（3032 张）；
- **但"每类约 500 张"并不准确**：实际范围是 **464 ~ 528**，极差 64 张；
  `A220` 最少（464），`Boeing737` 最多（528），两者相差 **13.8%**；
- 类别**大致均衡但不完全均衡**，最大/最小类比例为 **1.138 : 1**。
  → 因此评价指标**必须报告 Macro F1**（各类等权），不能只看 Accuracy。

### 4.2 图像属性

| 属性 | 实际情况 |
| --- | --- |
| 格式 | JPEG（`.jpg`） |
| 色彩模式 | **全部为 `L`（单通道灰度）**，非 RGB |
| 位深 | **uint8**，像素值范围 **0–255** |
| 尺寸 | **不固定**，共 **635 种**不同宽高组合 |
| 宽度范围 | 35 ~ 200 px，均值 91.6，中位数 89 |
| 高度范围 | 32 ~ 150 px，均值 83.0，中位数 80 |
| 单文件大小 | 平均 1.0 ~ 2.1 KB（按类别） |
| 损坏文件 | **0 张**（3032 张全部可正常解码） |
| 非灰度文件 | **0 张** |

> ⚠️ **尺寸不统一是必须处理的**：635 种尺寸意味着**不能直接送入网络**，
> 必须统一 resize。这也排除了"简单 padding 到最大尺寸"的方案（最大 200×150 会造成大量无效背景）。

**尺寸分布（用于确定统一输入分辨率）**：

| 门槛 | 满足"最短边 ≥ 该值"的图片占比 |
| --- | ---: |
| ≥ 48 px | 93.6% |
| ≥ 64 px | **77.4%** |
| ≥ 96 px | 24.6% |
| ≥ 128 px | 2.4% |

另有：宽或高 ≤ 64 px 的图片 **723 张（23.8%）**；宽或高 ≥ 128 px 的 **299 张（9.9%）**。

**结论**：均值 91.6×83.0 与中位数 89×80 都指向 **96×96** 附近，
即"统一到 96×96"时多数图片只需轻微缩放（既不会大幅上采样，也不会丢失细节）。
→ 主方案取 **96×96**（见 `experiment-plan.md` 第 3 节）。

### 4.3 亮度分布（重要）

对每类随机抽取 50 张统计：

| 类别 | 全图均值 | 类内标准差均值 |
| --- | ---: | ---: |
| A220 | 15.4 | 25.8 |
| A320321 | 16.2 | 23.7 |
| A330 | 12.8 | 22.8 |
| ARJ21 | 12.8 | 25.4 |
| Boeing737 | 15.4 | 25.3 |
| Boeing787 | 15.3 | 25.5 |

**全图均值只有 13~16（满量程 255）**，说明图像**绝大部分是黑色背景**，
飞机目标只占很小区域。

**影响**：

1. **不能直接使用 ImageNet 的均值/方差做归一化**（那是自然彩色图像的统计量）；
   应按**训练集**统计灰度均值/标准差后归一化，或改用简单的 `x/255` 缩放；
2. 若只做 `Resize + Normalize`，背景占比过高会让"背景"成为主导信号，
   模型可能学到"看背景亮度"而不是"看飞机形状"——这需要在错误分析中用 Grad-CAM 验证。

### 4.4 ⚠️ 重复图像（本次审计最关键的发现）

对 3032 个文件做 **MD5 逐字节比对**：

| 项目 | 数量 |
| --- | ---: |
| 总文件数 | 3032 |
| **唯一图像数** | **3010** |
| 重复哈希组 | **22 组**（涉及 44 个文件） |
| ├─ **类内重复** | **2 组** |
| └─ **跨类别重复** | **20 组** ← **标签冲突** |

**类内重复（2 组，同一类别内的完全相同的副本）**：

```

9cfc26e8e6   A330/086.jpg  ==  A330/427.jpg
```

**为什么这很严重**：

1. **标签本身矛盾**：同一张图不可能既是 A330 又是 Boeing787。
   这类样本对模型而言是**纯噪声**，会拉低准确率上限。
2. **会直接造成数据泄漏**：如果不去重就随机划分，
   这对相同图片**极可能一张进训练集、一张进测试集**，
   模型"背过答案"，测试分数被高估——
   **这与上一个 Iris 项目踩到的坑完全同类**（见 `learning-record.md`）。
3. **跨类重复占多数（20/22）**，说明这批数据在整理时可能有过
   **类别标注或文件拷贝环节的失误**。

**处理方案**（已写入 `experiment-plan.md` 第 2 节）：

- 先在**划分之前**按 MD5 去重；
- 对 20 组跨类别重复，**两侧样本全部剔除**（40 张），
  因为无法判断哪个标签是对的，保留任意一个都是引入错误标签；
- 2 组类内重复，**保留 1 张、删除 1 张**（2 张）；
- 去重后预期剩余 **3032 − 40 − 2 = 2990 张**（以脚本实际输出为准）；
- 去重清单会落盘保存，保证可追溯。

## 五、目录结构

```text
data/
├── README.md                      # 本文件
└── SAR-ACD/                       # git clone 得到的官方仓库
    ├── README.md                  # 官方说明（原文）
    ├── .git/                      # 官方仓库的 git 元数据
    └── images/                    # 图像本体
        ├── A220/        464 张   083.jpg ...
        ├── A320321/     510 张
        ├── A330/        512 张
        ├── ARJ21/       514 张
        ├── Boeing737/   528 张
        └── Boeing787/   504 张
```

原始图像文件名形如 `083.jpg`、`014.jpg`（三位数字，**类内编号**）。
注意：**不同类别目录下存在同名文件**（如 `A220/083.jpg` 与 `A320321/083.jpg`），
因此处理时**必须使用"类别/文件名"的相对路径**作为唯一标识，不能只用文件名。

## 六、关于数据是否进入版本管理

- **原始图像不进仓库**：`data/SAR-ACD/` 已写入项目根目录 `.gitignore`。
  原因：① 数据集许可证不明，公开再分发有法律风险；② 图像可由官方仓库重新克隆；
- **进入仓库的是**：本文件（统计结果）、去重清单、固定划分的索引文件（只含路径与标签）；
- **复现方式**：按第一节的 `git clone` 命令重新获取，再运行划分脚本即可重建全部实验输入。

## 七、一句话总结

> 官方说的是"每类约 500 张，共 3032 张"。
> **本地实测：每类 464~528 张，总数 3032 张；灰度、尺寸不固定（635 种）、整体偏暗；
> 并且存在 22 组重复图，其中 20 组是跨类别重复——这既会造成数据泄漏，也说明存在标注矛盾。**
> 这三条都必须在实验方案里正面处理，不能照抄官方数字直接开训。
