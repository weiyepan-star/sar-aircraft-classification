# 科研项目交付 Skill（Research Project Delivery）

一套**面向"要交给别人看"的实验项目**的交付约束。目标不是"跑出一个好数字"，
而是产出一份**别人能验证、能复现、能指出问题**的实验成果。

核心立场：

> **实验的价值不在于结果好不好看，而在于结论是否经得起复现和追问。**

---

## 何时使用

- 用户要求开展一个完整的实验/科研/课程项目（不限于机器学习）；
- 项目需要交付**代码 + 数据说明 + 实验方案 + 图表 + 报告**；
- 项目结果需要被他人（老师、评审、同事）检查或复现。

**不适用**：一次性的临时数据分析、纯探索性脚本、不需要交付的随手实验。

---

## 核心约束（硬性，不可协商）

> 每条约束都有编号（**G1–G8**），项目过程中引用编号即可，例如"此项符合 G2"。

### G1 · 先方案，后代码

**项目开工前必须先产出 `experiment-plan.md`，经确认后才能写代码。**

方案至少包含：

| 必有项 | 说明 |
| --- | --- |
| 研究问题 | 一句话说清要回答什么，并拆成可验证的子问题 |
| 先验预期 | **把假设写下来**，事后无论证实或推翻都如实记录 |
| 数据划分 | 比例、方式、随机种子、互不重叠的保证机制 |
| 数据处理 | 质量检查项、预处理、增强策略及其适用范围 |
| 对照设置 | 基线模型 + 待验证模型，说明每组的用途 |
| 评价指标 | 主指标与辅助指标，以及为什么选它 |
| 稳定性 | 种子数量与波动汇报方式 |
| 错误分析 | 分析什么、怎么分析 |
| 图表清单 | 先列出要产出哪些图，每张图回答什么问题 |
| 完成标准 | 可验收的、可判定的标准 |

**禁止行为**：方案未确认就大规模训练；先跑出结果再补方案（"倒着写方案"）。

> 方案里要明确标注**状态**（如"待评审"），确认后改为"已确认"并记录日期。

### G2 · 三集严格隔离，测试集只用一次

- 训练集 / 验证集 / 测试集 **严格隔离**，任何样本只能属于一个集合；
- **测试集仅在最终方案确定后评估**，全程原则上只评估一次；
- **严禁用测试集调参**：任何超参数、模型结构、阈值、早停、模型选择
  都**只能依据验证集**；
- 划分完成后必须**自动断言**：三个集合的样本标识交集为空；
- 若数据存在重复样本，**必须在划分之前去重**，
  否则同一内容的样本会跨集，等价于变相泄漏。

**判定**：如果测试集指标影响了任何一个"下一步决定"，即违规。

### G3 · 固定随机种子 + 分层抽样

- 数据集划分采用**固定随机种子**，保证任何人重跑得到**逐行一致**的划分结果；
- 划分方式为**分层抽样（stratified）**，保证每个类别在训练/验证/测试中的**比例一致**；
- 划分种子与训练种子**分离**：划分只做一次并冻结，
  所有对照模型**共用同一份划分索引文件**（否则模型之间不可比）；
- 划分结果必须**落盘**（如 `split_index.csv`），供逐行核对。

### G4 · 至少 3 个随机种子，报告均值与波动

- 正式实验必须使用**至少 3 个随机种子**；
- **必须报告均值与波动**（标准差或极差），并给出逐种子明细；
- **不得只保留最优单次结果**，也不得只报告最好看的那个种子；
- 比较两个方案时，需事先约定**稳健性判据**（例如"均值差需大于较大的那个标准差"），
  若差异落在波动范围内，**如实写"差异不显著"**，不得硬凑结论；
- 种子的固定范围应覆盖 `random` / `numpy` / `torch`（含 CUDA）/ `PYTHONHASHSEED`，
  并记录 DataLoader 的随机行为设定。

### G5 · 指标与图表全部由脚本自动生成

- 所有数字、表格、图表**必须由脚本自动生成**；
- **禁止手动修改数字、禁止手工编辑图片**；
- **禁止把数字手抄进报告**：报告应引用脚本产出的中间文件
  （如 `metrics.json` / `summary.csv`），保证"正文数字"与"脚本输出"同源；
- 每个图表的数值来源必须可追溯（哪份文件、哪个函数）；
- 若发现图表有误，**修改脚本重跑**，而不是修图。

**判定**：如果报告里的某个数字无法从产物文件里追溯出来，即违规。

### G6 · 失败与错误样例必须完整保留

- **低分、失败、错误、异常、不确定的样例必须完整保留，不能丢弃**；
- 保留范围包括：错分样本、高不确定性样本、训练失败或崩溃的运行记录、
  被否决的方案与其结果、低于基线的模型；
- 失败的运行同样要落盘（日志 + 指标 + 原因），
  **不得只保留成功的运行**；
- 报告中必须**正面分析失败**：为什么失败、失败在哪里，
  这往往比成功案例更有信息量。

**判定**：如果产出目录里只有"好的结果"，即违规。

### G7 · 图表必须服务正文问题

- 每张图必须对应正文中一个**具体问题**，且**在正文中被引用**；
- 不生成无意义的装饰图（凑数图、重复信息的图、只为好看的图）；
- 每张图必须配**三段式说明**：
  **「看什么」→「本次数值」→「所以说明什么」**；
- 图内文字语言与正文一致（中文报告用中文、英文论文用英文），
  并**自动校验**图内无缺字或语言不一致；
- 图表清单在方案阶段（G1）就应确定，新增图需说明它回答了什么问题。

### G8 · 最终必须可复现

- 项目最终满足**可复现要求**：`README.md` 完整，
  **在干净环境下可以复现全部结果**；
- README 必须包含：环境搭建、数据获取、运行步骤、预期产物、常见问题；
- **"干净环境"的定义**：仅有一份干净的代码副本，
  不依赖本机任何私有文件、绝对路径、手工步骤或未记录的缓存；
- 必须提供**一键运行**入口（如 `run_all.sh` / `run_all.ps1`）；
- README 里的命令**必须实际执行过**，不得凭记忆书写；
- 数据与环境不可入仓库时应写明**重建方式**（下载命令 / 环境定义文件）。

**验收方式**：想象从零开始，只按 README 操作，能否得到同样的产物。

## 强制流程（阶段门）

```text
① 方案阶段   → experiment-plan.md  【阶段门：方案未确认，禁止进入下一阶段】
② 代码阶段   → src/ 各脚本，每步先小样本冒烟测试
③ 实验阶段   → 全量 × 多种子 × 多对照，全部运行均落盘
④ 分析阶段   → 图表 + 错误分析 + 失败样例分析
⑤ 交付阶段   → 报告 + README + 干净环境复现验证
```

**阶段门规则**：

- ①→②：方案必须经确认（人在回路）；
- ②→③：所有脚本必须通过小样本冒烟测试；
- ③→④：多种子与全部对照必须跑完，**不得中途丢弃差的结果**；
- ④→⑤：必须有**干净环境复现验证**的记录（G8）。

## 项目目录结构约定

```text
<project>/
├── README.md                     # G8：完整复现说明
├── experiment-plan.md            # G1：方案（阶段门）
├── learning-record.md            # 过程记录：理解、决策、遗留疑问
├── environment.yml               # 环境定义，可重建
├── .gitignore                    # 排除数据本体、权重、中间产物
├── configs/                      # 实验参数（划分/模型/超参/种子）
├── data/
│   ├── README.md                 # 来源、引用、获取日期、本地实测统计
│   └── <dataset>/                # 数据本体（通常不入版本管理）
├── src/                          # 源代码
├── results/
│   ├── raw/                      # 逐次运行：日志、指标、划分索引、错误清单
│   └── summary/                  # 跨模型/跨种子的汇总表
├── figures/                      # 全部图表（矢量 + 位图）
├── report/                       # 报告
└── skills/                       # 项目使用的 Skill 与使用记录
```

**关键约定**：

- `results/raw/` 保留**每一次**运行（含失败的），这是 G6 的落地点；
- `data/README.md` 必须记录**本地实测统计**，不照抄官方数字；
- 图表同时输出矢量（`.pdf`）与位图（`.png`）。

## 交付前自检清单

逐条打勾，**任何一条不满足都不得声称"已交付"**：

| # | 对应约束 | 检查项 | 通过标准 |
| --- | --- | --- | --- |
| 1 | G1 | 方案先于代码 | `experiment-plan.md` 存在且标注"已确认" |
| 2 | G2 | 三集隔离 | 断言脚本通过，标识交集为空 |
| 3 | G2 | 测试集只用一次 | 能说清测试集被调用的次数与用途 |
| 4 | G3 | 划分可复现 | 重跑得到逐行一致的划分索引 |
| 5 | G3 | 分层生效 | 各集合类别比例偏差在容差内 |
| 6 | G4 | 种子数 | ≥ 3，且报告了均值与波动 |
| 7 | G4 | 无挑选 | 所有种子结果都在，无"只留最好" |
| 8 | G5 | 数字可追溯 | 报告每个数字都能由产物文件复算 |
| 9 | G5 | 图表脚本化 | 无手工修改数字/图片的痕迹 |
| 10 | G6 | 失败样例保留 | 错分/失败/低分样例与失败运行都在 |
| 11 | G7 | 图表有解读 | 每张图都有三段式说明且被正文引用 |
| 12 | G8 | 干净环境复现 | 有实际执行过的复现记录 |
| 13 | G8 | README 自洽 | 命令均执行过，无绝对路径与私有依赖 |

## 常见违规与后果

> 这些是真实项目中最常出现的违规，写在这里是为了**提前避坑**。

| 违规 | 后果 | 对应约束 |
| --- | --- | --- |
| 先跑代码后补方案 | 实验方向可能整体错误，返工代价最大 | G1 |
| 用测试集看了几眼再调参 | 测试集不再"未见"，指标失去意义 | G2 |
| 数据未去重就划分 | 重复样本跨集，测试分数被高估 | G2 |
| 每个模型各自随机划分 | 模型之间不可比，对比结论无效 | G3 |
| 只报最好的种子 | 结论建立在运气上 | G4 |
| 手改报告里的数字 | 报告与产物不一致，全部结论可疑 | G5 |
| 只保留高分结果 | 失去错误分析的全部信息量 | G6 |
| 图表堆砌不解读 | 审阅者无法判断结论从何而来 | G7 |
| README 命令没跑过 | 别人无法复现，交付不成立 | G8 |
